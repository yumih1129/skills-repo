# 资深 SKILL 质量评审器 使用手册

## 技能概述

**技能名称**：资深 SKILL 质量评审器

**标识**：`skill-evaluate`

**版本**：1.1.0

**功能**：从资深设计者、使用者、维护者和交付把关者视角，用证据、场景、门禁、量表和问题分级对任意 SKILL 做客观质量评审，输出可追溯的评分、修正建议和复评闭环。

---

## 快速开始

### 基本用法

直接给出目标 SKILL 路径和评估需求即可触发，例如：

```text
评估 .agents/skills/skill-create 的质量
```

```text
对 .agents/skills/news-briefing-search 做交付评审，看能不能直接上线
```

```text
帮我复查一下 .agents/skills/skill-manual-generate 修完之后还有没有问题
```

---

## 功能特性

### 支持的能力

| 能力 | 说明 |
|------|------|
| 六种评估模式 | 支持快速把关、标准评审、交付评审、引入前审查、定向复评和故障复盘，按需选择深度和输出形态 |
| 硬门禁检查 | G1-G5 五道硬门禁（结构可加载、触发可信、主任务可达、边界与安全可控、输出可验收），任一门禁失败即限制总体等级 |
| 12 维度量化评分 | 按 D1-D12 固定维度评分，每个维度有证据等级封顶、问题封顶和固定评分工作单，分数必须可追溯到文件证据 |
| 场景走查验证 | 至少覆盖正向触发、边界/误触发、缺资料/失败三类场景，高风险场景必须加入，验证真实链路可达性 |
| 问题分级与修正闭环 | 问题按 P0-P3 四级标注优先级、影响范围、修正动作和验收标准，支持修正后复评直到达标 |
| 封顶规则与最终判定 | 基线等级只允许降级，多条规则同时命中取最严格等级上限，存在未缓解 P0/P1 时强制限制总体等级 |

---

## 使用方式

### 适合的输入

- 给出目标 SKILL 目录路径，可选指定评估模式：`快速把关`、`标准评审`、`交付评审`、`引入前审查`、`定向复评`、`故障复盘`
- 可以只要求评估不修改文件，也可以要求评估后直接落地修正
- 可以指定"先给结论"输出结论版，也可以要求完整报告

### 执行特点

- 先完成证据采集、场景走查、门禁、评分、问题分级和最终判定，再一次性输出结论，不边评边追加阶段性结论
- 每个分数、问题和等级都能追溯到证据、影响和修正动作；没有证据的判断只标为待确认或降低置信度
- 同时评价设计质量和使用可达性——设计上合理但执行者读完不知道怎么用，不能判高分
- 只要求评估时不修改文件；要求修正时先固化评估基线再修改并复评

---

## 输出结果

### 结论版

用户要求"先给结论、简报、审阅"时使用。包含：最终或暂定结论、置信度和覆盖范围、是否可用/可交付/需修、影响结论的关键证据、最重要的问题、下一步动作。

### 完整报告

用户要求完整评审、交付评审或正式报告时使用。固定章节：摘要、证据范围、硬门禁结果、代表性场景走查、分维度评分、评分工作单、基线判定、问题清单与修正建议、最终判定、附录。文件名默认 `{slug}.md`。

### 修正交付

用户要求直接落地优化时使用。包含：已修问题清单、保留的原有能力、增强说明、复查的门禁/维度/场景、残留风险和后续复评入口。

## 使用示例

### 示例 1：主流程 — 标准评审

**输入**：

```text
对 .agents/skills/requirements-brief 做标准评审
```

技能采集证据 → 走查 3 个场景 → 检查 G1-G5 硬门禁 → 按 12 维度评分 → 问题分级 → 最终判定 → 输出完整报告或结论。

### 示例 2：边界 — 只评估不修改

**输入**：

```text
帮我评估一下 .agents/skills/skill-create 的质量，只看不改
```

技能完成评估后只输出报告和建议，不修改任何文件。

### 示例 3：交付产物 — 交付评审

**输入**：

```text
对 .agents/skills/skill-stabilize 做交付评审，出完整报告
```

技能按交付评审模式执行标准评审的全部动作，额外核验资源引用和输出契约，判定"可直接交付/有条件交付/不可交付"，输出符合模板规范的完整报告。

---

## 注意事项

1. 本技能只基于被评估 SKILL 的实际文件、可读取资源和可观察行为评分，不得用评估者经验替对象补齐缺失能力。
2. 先做硬门禁再做分维度评分；总分不能掩盖结构不可加载、触发失真、主流程不可达、安全边界失控或输出不可验收。
3. 最终等级只能降级，不能因亮点、用户接受或展示分回升；存在未缓解 P0 时总体不合格，存在未缓解 P1 时总体最多合格。
4. 发现高风险安全、来源不可信、恶意脚本或越权读写时，停止给"可引入/可交付"结论并提示触发 `skill-vetter`。
5. 已存在同名报告时，不得在旧报告末尾追加新版结果，必须按当前模板整体重写或另存为明确标识的新快照。
6. 评估与修正不得混在一起：先固化问题基线，再修正，再复评，避免依据丢失。

---

## 适用场景

- 新建、重构或重大改版 SKILL 的交付评审
- 对现有 SKILL 做质量自查、例行 review 或故障复盘
- 引入外部 SKILL 前判断质量、边界、依赖和是否需要安全审查
- 用户反馈"触发不准、步骤不好用、输出不可控"时定位设计缺陷
- 需要统一 SKILL 评价口径、评分标准、修正优先级和复评闭环
