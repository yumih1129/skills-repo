# 资深 SKILL 质量评审器 使用手册

## 技能概述

**技能名称**：资深 SKILL 质量评审器

**标识**：`skill-evaluate`

**版本**：1.0.0

**功能**：对任意 SKILL 做证据化质量评审、客观评分、问题分级、交付把关与复评闭环。

---

## 快速开始

### 基本用法

直接描述你的评估需求即可触发该技能，例如：

```text
评估一下这个SKILL的质量
新建的SKILL需要交付评审
对现有技能做质量自查
外部SKILL引入前需要审查
```

---

## 功能特性

### 支持的能力

| 能力 | 说明 |
|------|------|
| 快速把关 | 日常筛查，1-2个场景，最终等级最高为良好 |
| 标准评审 | 常规质量评估，3类场景走查，完整评分与修正清单 |
| 交付评审 | 新建或重大改版最终把关，含高风险场景验证 |
| 引入前审查 | 外部SKILL接入前质量与安全边界评估 |
| 定向复评 | 已修正后的局部复查，确认修正是否关闭 |
| 故障复盘 | 误触发、失败输出或维护事故根因定位 |

### 评估维度

| 维度 | 权重 | 说明 |
|------|------|------|
| D1 元数据与结构规范性 | 8% | 可加载、可定位、可按资源职责维护 |
| D2 触发准确性与发现性 | 10% | 正确场景触发并避免误触发 |
| D3 目标契合与边界控制 | 9% | 清楚解决什么、不解决什么、前提 |
| D4 流程完整性 | 11% | 覆盖准备、执行、交付、失败、闭环 |
| D5 执行确定性 | 11% | 步骤具体、可复现、少猜测 |
| D6 用户交互与权限治理 | 9% | 询问、确认、授权、越权防护 |
| D7 资源策略与渐进加载 | 8% | 核心自包含，长资料按需加载 |
| D8 安全、依赖与环境假设 | 8% | 网络、脚本、文件、敏感信息可控 |
| D9 输出契约与可验收性 | 10% | 交付物、格式、验收标准明确 |
| D10 验证、测试与场景覆盖 | 6% | 真实走查、验证和复评 |
| D11 可维护性与可迭代性 | 6% | 易改、易定位问题、闭环清楚 |
| D12 领域适配与复用价值 | 4% | 贴合领域且可复用 |

### 硬门禁

| 门禁 | 说明 | 失败后果 |
|------|------|----------|
| G1 结构可加载 | SKILL.md存在可读，frontmatter可解析 | 不合格 |
| G2 触发可信 | description同时说明能力和触发场景 | 不合格 |
| G3 主任务可达 | 执行者读完知道下一步做什么 | 不合格 |
| G4 边界与安全可控 | 明确做/不做、风险处理 | 不合格/最多合格 |
| G5 输出可验收 | 定义交付物、格式、完成标准 | 最多合格 |

### 问题分级

| 级别 | 说明 |
|------|------|
| P0 | 阻塞加载、触发、主流程、交付或严重安全边界 |
| P1 | 高频场景误导执行、结果不可信或用户失控 |
| P2 | 影响维护、复用、边缘场景或长期稳定性 |
| P3 | 表达优化、轻量增强、示例补充 |

## 使用方式

### 适合的输入

- 新建、重构或重大改版SKILL的交付评审
- 现有SKILL质量自查、例行review、故障复盘
- 外部SKILL引入前，判断质量、边界、依赖
- 用户反馈"触发不准、步骤不好用、输出不可控"时定位设计缺陷
- 统一SKILL评价口径、评分标准、修正优先级

### 执行特点

- 先做硬门禁，再做分维度评分，总分不能掩盖结构问题
- 先完成证据采集、场景走查、门禁、评分，再一次性输出结论
- 每个分数和问题都必须能追溯到证据、影响和修正动作
- 判级必须先按未四舍五入的raw_total得出基线等级，再按封顶规则降级

---

## 输出结果

### 结论版

- 最终结论、置信度和评估覆盖范围
- 是否可用/可交付/需修/不可交付
- 影响结论的关键证据
- P0/P1/P2/P3中最重要的问题
- 下一步建议动作

### 完整报告

按固定模板输出，包含：
- 摘要（最终判定回填）
- 证据范围
- 硬门禁结果
- 代表性场景走查
- 分维度评分（含评分工作单）
- 基线判定（非最终结论）
- 问题清单与修正建议
- 最终判定（唯一终局结论）
- 附录

### 修正交付

- 本轮修正了哪些问题
- 保留了哪些原有能力
- 触发、流程、交互、验收如何增强
- 修改后复查了哪些门禁、维度和场景
- 残留风险和后续复评入口

## 使用示例

### 示例1

**输入**：

```text
评估一下这个新建的SKILL质量，需要交付评审
```

**输出**：

完整评估报告，包含G1-G5硬门禁结果、12维度评分（raw_total）、基线等级、问题清单（P0-P3）、最终等级（优秀/良好/合格/不合格）、交付建议。

### 示例2

**输入**：

```text
快速把关一下这个SKILL是否可用
```

**输出**：

快速结论版，包含核心文件检查、1-2个场景走查、可用/需修/不可用判断、最终等级最高为良好。

### 示例3

**输入**：

```text
根据评估结论修正那个SKILL的问题并复评
```

**输出**：

修正后的SKILL文件清单、修改范围、复评结论，确认问题是否关闭。

## 注意事项

1. 只基于被评估SKILL的实际文件评分，不得用经验替对象补齐缺失能力
2. 先做硬门禁再评分，任一硬门禁失败总体等级直接不合格
3. 评分工作单必须记录coverage_score、evidence_cap、issue_cap、mode_or_resource_cap
4. raw_total使用未四舍五入值判级，8.99仍为良好，7.79仍为合格
5. 核心维度D2/D4/D5/D9任一低于7.5分不得给出稳定交付建议
6. 用户只要求评估时不得修改文件
