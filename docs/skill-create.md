# SKILL 创建闭环向导 使用手册

## 技能概述

**技能名称**：SKILL 创建闭环向导

**标识**：`skill-create`

**版本**：1.0.0

**功能**：将用户意图、领域资料或已有过程沉淀为可触发、可执行、可维护、可迭代的 SKILL，并通过结构排查闭环和质量评估闭环持续修正，直到达到交付标准。

---

## 快速开始

### 基本用法

直接描述要创建的 SKILL 名称、用途和场景即可，例如：

```text
帮我创建一个 news-briefing-search 技能，用于根据时间检索新闻并整理为简报
```

```text
把这段对话里的需求梳理流程沉淀为一个 requirements-brief SKILL
```

```text
根据这份评估报告修复 .agents/skills/skill-create 的问题，直接改
```

---

## 功能特性

### 支持的能力

| 能力 | 说明 |
|------|------|
| 四种任务模式 | 支持 `create/refactor`（新建/重构）、`fix/optimize`（修正/优化）、`evaluate-only`（仅评估）、`archive-only`（仅归档），按阶段 0 分流规则自动判断 |
| 结构化资源设计 | 按固定职责分配 `SKILL.md`（核心流程）、`references/`（长资料）、`scripts/`（确定性脚本）、`assets/`（输出素材），禁止冗余和越界 |
| 结构排查闭环 | 深度排查触发准确性、边界清晰度、流程完整性、自包含性、可执行性等 8 个维度，问题逐项修正后重新排查，直到通过 |
| 质量评估闭环 | 从规范性、触发性、完整性、可执行性、交互性、独立性、可迭代性、可维护性 8 个维度评分，不达标项进入修正并复评，直到达到"良好"或以上 |
| 评估防误判 | 内部原始值与对外展示值严格区分，阈值比较基于未四舍五入值，防止 `7.785 -> 7.8 -> 良好` 等展示值导致的越级判定 |
| 验证与归档 | 修改后复查 frontmatter、路径和闭环关系，支持场景走查验证；可复用过程资产按目录规范归档 |

## 使用方式

### 适合的输入

- 给出 SKILL 名称、用途描述、典型触发场景和参考资料（目录、代码、文档或过往对话）
- 给出已有评估报告和要求修正的问题清单
- 要求归档某个创建过程中的可复用提示词、决策框架或评估规则
- 可指定目标输出位置，未指定时默认 `skills/{skill-name}/`

### 执行特点

- 先确定边界，再创建内容；先形成最小可用版本，再补强复杂能力
- 设计决策与执行修改分开：先给结论让用户审阅，确认后再改
- 优化已有 SKILL 时保留仍然有效的原始能力，新增规则只补足缺口、收窄歧义或增强验收
- 每次修改后必须复查受影响文件，确认没有破坏 frontmatter、触发描述、执行流程和闭环关系

---

## 输出结果

### create/refactor 模式

说明创建或重构了哪些核心能力、目标 SKILL 路径、目录和资源组织方式、验证内容和残留风险。

### evaluate-only 模式

只输出评估结论、证据、风险和修正建议，不修改文件。摘要只展示最终等级、交付结论、置信度和关键结论，不暴露 `raw_total`、基线等级等中间变量。

### fix/optimize 模式

说明修正了哪些问题、保留了哪些原能力、触发/流程/交互/验收如何增强、验证内容和残留风险。

### archive-only 模式

说明归档了哪些可复用资产、存放位置和后续复用方式。

## 使用示例

### 示例 1：主流程 — 新建 SKILL

**输入**：

```text
创建一个 requirements-brief 技能，把用户口语化需求整理为结构化需求简报。
典型场景：用户说"帮我整理一下刚才讨论的需求"，技能输出正式的 Markdown 需求简报。
```

技能按阶段 0-8 依次执行：立项定边界 → 学习资料 → 设计资源目录 → 生成 SKILL.md → 统一命名 → 结构排查 → 质量评估 → 验证，最终交付可用的 SKILL 目录。

### 示例 2：边界 — 仅评估不修改

**输入**：

```text
评估一下 .agents/skills/skill-create 的质量，只看不改
```

技能进入 `evaluate-only` 模式，完成证据采集、门禁检查、场景走查、评分、问题分级和最终判定，输出单一终局报告，不修改任何文件。

### 示例 3：修正 — 基于评估结论落地修改

**输入**：

```text
根据评估报告修复 .agents/skills/skill-manual-generate，直接改
```

技能进入 `fix/optimize` 模式，以评估结果为问题基线逐项修正，保留有效能力，修改后复评受影响维度并验证。

## 注意事项

1. 本技能只创建、修正和评估 SKILL 本体；用户只要求独立评估已有 SKILL 且环境中存在更专门的评估能力（如 `skill-evaluate`）时，应转交专门能力。
2. 核心执行流程不得依赖另一个 SKILL 才能理解——外部引用只能作为可选资料，不得承担核心流程。
3. 删除已有能力、改变触发范围、拆分/合并 SKILL、引入外部依赖或新目录结构时，必须先让用户确认。
4. 评估摘要不得暴露 `raw_total`、基线等级、待确认规则等中间变量，且所有阈值比较必须基于未四舍五入的内部原始值，防止展示值越级判定。
5. `SKILL.md` 只放核心触发、流程、选择规则、质量门禁和失败处理；长资料、脚本和素材按需放入对应子目录，不堆砌在核心文件中。

---

## 适用场景

- 从零创建新的 SKILL，将领域知识或已有流程沉淀为可执行能力
- 重构现有 SKILL，收窄歧义或增强可执行性
- 根据评估结论修正 SKILL 的缺陷和短板
- 将创建过程中产生的提示词模板、决策框架、评估规则归档为可复用资产
- 在创建/重构/修正闭环内对当前 SKILL 做自评或复评
