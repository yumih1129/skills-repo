# SKILL 创建闭环向导 使用手册

## 技能概述

**技能名称**：SKILL 创建闭环向导

**标识**：`skill-create`

**版本**：1.0.0

**功能**：用于创建、重构、修正和归档任意 SKILL，并通过结构排查、质量评估与验证形成可交付闭环。

---

## 快速开始

### 基本用法

直接描述你的需求即可触发该技能，例如：

```text
帮我创建一个新闻搜索SKILL
这个SKILL需要优化，评估一下问题
把当前的代码审查流程沉淀为SKILL
根据评估结论修正这个技能
```

---

## 功能特性

### 支持的能力

| 能力 | 说明 |
|------|------|
| 新建 SKILL | 从零创建完整的 SKILL 目录和核心文件 |
| 重构 SKILL | 重新设计已有 SKILL 的结构和流程 |
| 修正优化 | 根据评估结论或问题清单修正现有 SKILL |
| 归档沉淀 | 将可复用过程资产沉淀为独立 SKILL |
| 独立评估 | 仅输出评估报告，不修改文件 |
| 质量闭环 | 结构排查 + 质量评估 + 修正复评 |

### 任务模式

| 模式 | 触发条件 | 执行内容 |
|------|----------|----------|
| `create/refactor` | 新建、重构或沉淀领域知识 | 完整执行阶段1-8 |
| `fix/optimize` | 根据评估结论或缺陷修正 | 进入受影响阶段执行修正 |
| `evaluate-only` | 仅要求评估审查 | 只执行评估，输出报告不修改文件 |
| `archive-only` | 只要求沉淀过程资产 | 直接进入归档，不改动核心 SKILL |

---

## 使用方式

### 适合的输入

- 创建一个新的 SKILL（给出名称、场景、参考资料）
- 重构或优化已有 SKILL
- 将领域知识、工作流程沉淀为可复用 SKILL
- 根据评估报告修正 SKILL 问题
- 需要独立评估 SKILL 质量

### 执行特点

- 先确定边界，再创建内容，追求一次成型
- 每个阶段有明确输入、动作、输出和通过标准
- 设计决策与执行修改分开，先给结论让用户审阅
- 评估不是结束，不达标项必须进入修正闭环
- 保持上下文经济，SKILL.md 只放核心流程

---

## 执行流程

### 阶段 0: 立项与边界

判断任务模式，命中后立即停止不再继续匹配：

1. **archive-only**：只沉淀过程资产，不改动核心 SKILL
2. **fix/optimize**：根据问题清单修正优化，先固化问题清单
3. **evaluate-only**：只评估不修改（需满足特定条件）
4. **create/refactor**：新建、重构或沉淀 SKILL，执行阶段1-8

### 阶段 1: 学习与资料整理

深度阅读用户提供的资料，提取对执行有直接价值的信息。

整理维度：任务场景 → 输入要求 → 操作步骤 → 输出格式 → 质量规则 → 常见错误 → 决策点 → 可复用资源

### 阶段 2: 资源设计

判断是否需要额外资源。资源分配：

- `SKILL.md`：核心触发、流程、选择规则、质量门禁
- `references/`：领域资料、规范、示例
- `scripts/`：确定性执行程序
- `assets/`：模板、图片、样例工程

### 阶段 3: 生成或更新 SKILL

- 新建：创建 `{skill-name}/SKILL.md`
- 更新：读取现有内容，保留有效能力，移除过时内容
- frontmatter 只保留 `name` 和 `description`

### 阶段 4: 统一命名与结构

- 目录和文件使用 kebab-case
- 过程资料按步骤编号

### 阶段 5: 结构排查闭环

深度排查"是否完整、是否自洽、是否可执行"，列出问题、影响和建议动作。

### 阶段 6: 分析决策与用户确认

必须让用户确认的情况：
- 删除已有能力、文件或资源
- 拆分或合并 SKILL
- 改变触发范围
- 引入外部依赖或新目录结构
- 对用户原始意图做明显收窄或扩展

### 阶段 7: 质量评估闭环

评分维度（按顺序）：规范性 → 触发性 → 完整性 → 可执行性 → 交互性 → 独立性 → 可迭代性 → 可维护性

结论等级：
- 优秀：可直接使用
- 良好：可用，有少量非阻塞优化项
- 合格：基本可用，需修正明显短板
- 不合格：核心流程存在重大缺陷

### 阶段 8-9: 修正与归档

未达标项进入修正闭环，修正后重新评估。archive-only 模式直接进入归档。

---

## 输出结果

### 评估报告（evaluate-only）

- 最终等级（优秀/良好/合格/不合格）
- 交付结论
- 置信度
- 关键结论
- 问题分级与修正建议

### 完整 SKILL 包

- `SKILL.md`：核心触发、流程、规则
- `references/`：补充资料（按需）
- `scripts/`：程序脚本（按需）
- `assets/`：素材资源（按需）

## 使用示例

### 示例1

**输入**：

```text
帮我创建一个"技术文档审查"SKILL，用于自动化审查代码文档质量
```

**输出**：

完整 SKILL 目录，包含 SKILL.md、frontmatter、触发描述、执行流程、质量门禁、失败处理等全部核心内容。

### 示例2

**输入**：

```text
评估一下这个SKILL的质量问题
（用户提供SKILL路径）
```

**输出**：

评估报告，包含等级判定（优秀/良好/合格/不合格）、详细评分维度分析、问题分级、修正建议。不修改任何文件。

### 示例3

**输入**：

```text
根据评估报告修正那个SKILL的问题
```

**输出**：

修正后的 SKILL 文件，每项修改都有明确说明，修正后自动复评。

---

## 注意事项

1. 评估不是结束，凡是不达标项都要进入修正闭环并重新评估
2. 设计决策与执行修改分开，先给结论让用户审阅，确认后再改
3. 优化已有 SKILL 时必须保留仍然有效的原始能力，不得用简化替代能力完整性
4. evaluate-only 模式若环境中存在更专门的评估能力，且不符合特定条件，应转交专门评估能力
5. 删除能力、拆分合并、改变触发范围等操作必须先让用户确认
