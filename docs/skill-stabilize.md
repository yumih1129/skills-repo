# SKILL 收口稳定器 使用手册

## 技能概述

**技能名称**：SKILL 收口稳定器

**标识**：`skill-stabilize`

**版本**：1.0.0

**功能**：对已有 SKILL 做不改变能力边界的收口稳定化优化，减少歧义与漂移，提升重复评测一致性，并将评估结论直接落地为修订结果。

---

## 快速开始

### 基本用法

直接指定目标 SKILL 即可触发收口优化，例如：

```text
优化一下这个SKILL的表达和规则
帮我把这个skill的歧义消除掉
根据评估结论修订这个技能
提升这个SKILL的稳定性
```

---

## 功能特性

### 支持的能力

| 能力 | 说明 |
|------|------|
| 漂移源识别 | 识别模板选择、输入范围、读取顺序等12类可能导致同一输入不同结果的漂移源 |
| 三重判断修改 | 确保修改不会改变功能、性能或效果，只消除歧义增强确定性 |
| 机械规则收敛 | 把"建议、通常、优先"收敛成"必须、固定、按顺序"，提升执行一致性 |
| 多文件职责处理 | 固定多文件SKILL的权威顺序，主文件保留流程，资源文件只承担局部细节 |
| 评估结论落地 | 把评估结论直接修订到目标SKILL文件中 |
| 双重模式 | 支持analysis（只分析）和edit（直接修改）两种输出模式 |

### 硬边界约束

以下约束必须同时满足，任一不满足时不进入收口修改：

1. 不改变功能边界、触发条件、输入输出、执行方式、性能要求和交付效果
2. 不引入依赖外部上下文才能理解的内容
3. 不新增模糊词、可多解条件、隐含例外或临场判断
4. 不用软词替代规则，能枚举就枚举，能固定就固定
5. 不删除必要门禁、失败处理、边界控制或回退机制
6. 不把资源文件变成新的自由发挥空间
7. 所有修改都必须能追溯到目标SKILL及其本地资源
8. 无法机械化的内容标记为"有意边界"保留
9. 可以收掉的内容必须收掉

## 使用方式

### 适合的输入

- 优化、提升、收口、稳定已有 SKILL 的表达与规则
- 减少歧义、减少漂移、增强自包含或提高重复评测一致性
- 把评估结论直接落地成修订结果
- 梳理多文件 SKILL 的权威顺序、资源职责

### 不适用场景

- 新建全新 SKILL 或扩能力、扩边界、改触发范围
- 只要求独立评估、评分、审查而不要求修改
- 恶意脚本、来源可信度或权限风险审查

### 输入字段

| 字段 | 说明 |
|------|------|
| SKILL_ROOT | 目标 SKILL 根目录（必需） |
| output_mode=analysis | 只做分析，不修改文件 |
| output_mode=edit | 直接修改目标文件 |

### 执行流程

#### 阶段 0: 确定对象与模式

- 确认目标 SKILL 路径、输出模式
- 判断是否需要分流到 skill-evaluate 或 skill-create

#### 阶段 1: 通读本地文件并建立证据表

- 读取目标 SKILL 目录及所有本地资源
- 建立文件清单、职责清单和权威顺序
- 记录规则在主文件与资源文件的分布

#### 阶段 2: 识别漂移源

按以下顺序检查12类漂移来源：
1. 模板选择
2. 输入范围
3. 读取顺序
4. 优先级
5. 示例选择
6. 失败处理
7. 记录口径
8. 重复表述
9. 可选条件
10. 降级路径
11. 资源文件职责不清
12. 自由解释空间

#### 阶段 3: 三重判断候选修改

每个候选修改必须同时满足：
1. 不会改变功能、性能或效果
2. 只是消除歧义、增强确定性
3. 让同一输入多次运行结果更稳定

#### 阶段 4: 收敛为机械规则

- 固定顺序
- 固定枚举
- 固定优先级
- 固定门禁
- 固定失败路径
- 固定输出结构
- 固定权威来源

#### 阶段 5: 处理多文件职责

- 先固定权威顺序
- 主文件保留流程、选择规则、门禁、失败处理
- 资源文件只保留局部细节、模板、参考、素材

#### 阶段 6: 执行改写

改写规则：
- "建议、通常、优先、尽量" → "必须、只、固定、按顺序"
- 模糊描述 → 可判定列表
- 多个可能路径 → 单一优先级链
- 自由选择 → 固定顺序/阈值/范围
- 失败处理 → 明确停止/提示/降级/回退规则
- 重复内容 → 一句权威定义，其他只引用

#### 阶段 7: 复核闭环

检查是否仍存在：
- 同一输入不同结论的地方
- 重复规则来源
- 资源文件职责越界
- 可由更机械写法替代的表述
- 误改的功能边界、触发条件等

---

## 输出模式

### analysis 模式

1. 结论：是否需要修改，是否已足够稳定
2. 漂移源清单，按严重性排序
3. 每个问题的漂移原因及修改建议
4. 总体判断：是否已接近闭合

### edit 模式

1. 结论：是否需要修改
2. 可落地的修订结果
3. 精确 patch 或完整替换文本
4. 哪些问题已收掉，哪些属于有意保留的边界

## 使用示例

### 示例1

**输入**：

```text
优化一下这个SKILL的表达和规则，output_mode=edit
```

**输出**：

直接修改目标 SKILL 文件，消除歧义，统一权威口径，提升执行一致性。

### 示例2

**输入**：

```text
分析一下这个SKILL的稳定性问题
```

**输出**：

analysis 报告，包含漂移源识别结果、严重性排序、修改建议。

### 示例3

**输入**：

```text
根据评估结论修订这个技能
（附评估报告）
```

**输出**：

将评估结论中的问题直接落地为 SKILL 修订结果，明确哪些已收掉，哪些为有意边界。

---

## 注意事项

1. 不改变任何功能边界、触发条件、输入输出、执行方式、性能要求和交付效果
2. 只能消除歧义、增强确定性、统一权威口径，不能扩展能力
3. 无法机械化的内容标记为"有意边界"保留，不强行收口
4. analysis 模式只输出分析结果，不修改文件
5. 扩能力、改边界、改触发范围时停止并转交 skill-create

---

## 适用场景

- 消除已有 SKILL 的歧义表述和规则漂移
- 提升同一输入多次执行的结果一致性
- 统一多文件 SKILL 的权威顺序和资源职责
- 把评估结论直接落地为可执行修订
- 收口已有 SKILL 使其更稳定、更可维护
