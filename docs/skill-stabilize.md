# SKILL 收口稳定器 使用手册

## 技能概述

**技能名称**：SKILL 收口稳定器

**标识**：`skill-stabilize`

**版本**：1.0.0

**功能**：在不改变功能边界、触发条件、输入输出和交付效果的前提下，对已有 SKILL 做收口稳定化优化，消除歧义、减少漂移、统一权威来源，并将评估结论直接落地为可执行修订。

---

## 快速开始

### 基本用法

直接描述你的任务需求即可触发该技能，例如：

```text
帮我把 .agents/skills/skill-create 收口一下，消除歧义
```

```text
对这个 SKILL 做稳定化优化，只分析不修改文件
```

```text
把评估结论直接落地到 .agents/skills/skill-evaluate 的 SKILL.md
```

---

## 功能特性

### 支持的能力

| 能力 | 说明 |
|------|------|
| 漂移源识别 | 按 12 类固定检查项扫描目标 SKILL，定位所有可能导致同一输入产生不同结果的表述或结构问题 |
| 三重安全判断 | 对每个候选修改依次判断：是否改变功能/性能/效果、是否只消除歧义增强确定性、是否让结果更稳定；三项全部通过才允许修改 |
| 机械规则收敛 | 将模糊表述压成固定顺序、固定枚举、固定优先级、固定门禁、固定失败路径和固定输出结构 |
| 多文件职责梳理 | 固定多文件 SKILL 的权威顺序，主文件保留流程与门禁，资源文件只承担模板/素材/脚本职责，同一条规则只有一个权威来源 |
| 双模式输出 | 支持 `analysis`（只分析不修改）和 `edit`（直接修改目标文件）两种模式 |
| 复核闭环 | 修改后按固定顺序复跑最小场景、边界场景和失败场景，确保不再存在可安全收口项 |

---

## 使用方式

### 适合的输入

- 给出目标 SKILL 根目录路径和输出模式（`analysis` 或 `edit`）
- 直接要求"优化""收口""稳定""规范"已有 SKILL，并明确是否允许修改文件
- 把已有评估报告/结论作为输入，要求落地为 SKILL 修订

### 执行特点

- 先通读目标 SKILL 的全部本地文件，建立证据表和权威顺序，再进入分析
- 对漂移源按 S1（影响触发/执行/输出/权限）到 S4（仅影响表达）四个严重等级排序
- 只做收口，不扩能力、不改边界、不改触发范围；超出收口边界时自动停止并说明原因
- 仅要求独立评估时自动转交 `skill-evaluate`，不伪装成优化闭环

---

## 输出结果

### analysis 模式

按顺序输出：是否需要修改的结论、仍然存在的漂移源（按严重性排序）、每个问题的漂移原因和修改判断、总体闭合状态。

### edit 模式

按顺序输出：是否需要修改的结论、可直接落地的修订结果、已收口项和有意保留的边界说明。单文件输出完整替换文本，多文件输出精确 patch。

## 使用示例

### 示例 1：主流程 — 收口单文件 SKILL

**输入**：

```text
把 .agents/skills/news-briefing-search 做收口优化，直接改文件
```

技能将通读目标目录、建立证据表、识别漂移源、三重判断后直接修改 SKILL.md，并复核确认。

### 示例 2：analysis 模式 — 只分析不修改

**输入**：

```text
帮我分析 .agents/skills/requirements-brief 有没有漂移问题，不要改文件
```

技能将输出漂移源清单、严重性排序和每个问题的分析结论，不修改任何文件。

### 示例 3：边界场景 — 请求超出收口范围

**输入**：

```text
帮 skills/xxx 加一个联网搜索的新能力
```

技能检测到请求涉及扩能力、改边界，超出收口范围，将停止并建议转交 `skill-create` 或重构流程。

---

## 注意事项

1. 本技能只在现有能力边界内收口，不用于新建 SKILL、扩展能力或改变触发范围。
2. 某项内容继续收口会改变功能、性能或效果时，保留原内容并标记为"有意边界"，不会强行机械化。
3. 目标目录不可读或本地资源冲突无法判定权威来源时，停止修改并报告阻塞原因。
4. 多文件 SKILL 中同一条规则只能有一个权威来源，其他位置只引用不复制；主文件不承担模板/素材职责，资源文件不承担流程/判定规则。
5. 删除能力、改变触发范围、引入新外部依赖、拆分或合并 SKILL 均会触发停止并说明已超出收口边界。

---

## 适用场景

- 已有 SKILL 存在歧义表述或多解条件，导致不同执行者得出不同结论
- 多文件 SKILL 中同一规则在多个文件重复出现且口径不一致
- 需要在不改交付效果的前提下，将模糊建议收敛为机械判定规则
- 需要把评估或审查结论直接落地为可执行修订
- 需要梳理 SKILL 各文件的权威顺序和职责边界
