# 主题规范

本文件是当前技能的自包含主题规范。它已经把历史校准信息内化到技能目录内部，执行本技能时不再要求读取任何技能目录外资源。

## 权威顺序

主题相关规则按以下顺序生效：

1. `references/theme-spec.md`：定义每个主题的组件职责、结构语法和禁止漂移项。
2. `assets/theme-presets.js`：定义脚本渲染用的样式 token。
3. `references/render-contract.md`：定义组件如何进入内部结构。
4. `SKILL.md`：定义何时触发、何时交付、如何复评。

若 `theme-presets.js` 与本文件冲突，以本文件为准修正。

## 统一原则

1. 同一主题的组件语法固定，不允许混用其他主题组件。
2. 同一主题下，内容可以变，组件长相不能变。
3. 标题、导语、提示块、二级标题、三级标题、引用、表格、题注和代码块是重点对齐对象。
4. 本文件中已定义的组件，输出时必须优先沿用；不能用“通用模板感”替代。
5. 本文件中未定义的组件，新增时只能使用与该主题一致的低风险写法。
6. 所有内置主题的表格都必须沿用同一套完整表格结构基线：整表有统一主题底色，表头、首列强调和普通正文格只允许做同色系层次变化，不允许退回成“只有表头或首列有色，其余大面积纯白”。
7. 站在手机端阅读视角，表格单元格文字必须默认比正文小一号；正文通常保持 `15px`，表格内部单元格默认收为 `14px`，但 `table-label` 与 `table-note` 不跟随缩小。
8. 只有 `academic-paper-template` 允许正文段落与收尾段落保留 `2em` 首行缩进；其他主题的 `paragraph`、`calloutText` 与 `closing` 必须不缩进。

## 视觉质量底线

无论使用哪个主题，最终版式都必须同时满足：

- `整齐`：同层级组件的边距、对齐和视觉重量稳定，不出现一会儿像论文、一会儿像营销海报的断层。
- `精美`：强调色、边框、圆角和底色有克制感，不能为了“好看”堆叠过多装饰。
- `清爽`：留白足够但不过度松散，正文始终是页面主角。
- `可读`：标题有信息层级，导语有引入作用，正文密度适合手机端连续阅读。
- `克制`：高强调块只服务重点信息，不得连续堆叠多个 `callout`、引用或装饰性标题造成视觉噪声。

## 组件词汇表

- `eyebrow`：标题前的主题标签段落
- `lead`：标题后的主导语
- `callout`：导语后的提示块或概览块
- `meta`：标题后、摘要前的前置信息行
- `keywords`：摘要后的关键词行
- `h2`：主章节标题
- `h3`：局部小标题
- `quote`：引用块
- `table-label`：表格题签
- `table-note`：表格说明或图注式说明
- `code-block`：代码块

## 主题画像与组件锚点

### `wechat-native-template`

定位：

- 这是未指定主题时的默认主题。
- 它同时承担整篇回退主题职责：当其他主题无法映射 `eyebrow`、`meta`、`keywords`、`callout` 等组件时，允许回退到本主题，用更克制的微信原生写法完整承接内容结构。

组件锚点：

- `eyebrow` 可选；作为回退主题时，使用轻量、小字号、弱强调的主题标签段落
- `meta` 为标题后的轻量居中信息行
- `keywords` 为摘要后的轻量关键词行
- `callout` 为浅青底、左强调线的说明块
- `h1` 为居中轻边框圆角标题卡
- `lead` 为浅青底、左强调线的单段导语
- `h2` 为胶囊式浅底标题
- `quote` 为浅青底轻卡片
- 正文段落、提示块正文与收尾均不使用首行缩进
- 表格为完整边框结构，整表为浅青白底，表头更深一层，首列只做轻量加重，单元格字级较正文小一号
- 代码块为浅底细边框

禁止漂移：

- 不得把“回退到微信原生”理解成可以自由拼样式；即使承接额外组件，也必须保持原生轻量语法
- 不得把 `h2` 改成纯文本下划线风
- 不得给 `h3` 增加胶囊或块状背景

### `academic-paper-template`

定位：

- 这是论文主题的规范键名。
- 它不是未指定主题时的默认样式；未指定主题时，默认仍是 `wechat-native-template`。

组件锚点：

- 无 `eyebrow`
- `h1` 为居中论文式标题
- 标题后是论文式前置信息：作者、单位、日期
- `lead` 必须按严格论文摘要写法处理：`摘要：` 作为行内标签，后接单段摘要正文，不使用卡片、底色、圆角或营销导语块
- 摘要后有 `keywords` 行，采用 `关键词：词 1；词 2；词 3` 的行内论文写法
- `callout` 仅用于论文语境内的“研究提示 / 方法说明 / 核心发现 / 注”类短块，采用白底、上下细线、无圆角、无品牌色的学术注记写法；标签可使用“研究提示”“方法说明”“核心发现”“注”等自然中文，不使用全大写营销标签
- `h2` 为左对齐纯文本学术标题，不加色块、边线、圆角或装饰胶囊
- `h3` 为左对齐次级学术标题，只保留字号层级差，不引入装饰性视觉语法
- `quote` 仅保留左细线，不做卡片
- 正文与收尾保留 `2em` 首行缩进；摘要、关键词行与引用正文不缩进
- 表格必须使用严格三线表：白底、顶线、表头下横线、底线，不使用整表底色、卡片底色、首列色块或圆角
- 代码块为白底细边框的附录式呈现，禁用深底卡片、圆角代码框和品牌色强调
- 正文、摘要、引用、表格说明和收尾都使用衬线字体与论文式行距，不混入公众号强调块语言

禁止漂移：

- 不得加入营销卡片、胶囊标题或品牌色强调块
- 不得把 `callout` 渲染成公众号提示卡、彩色信息块、左侧强强调线或圆角卡片；若内容不属于研究提示、方法说明、核心发现或注记语义，应改为普通段落、引用或表格，而不是强行使用 `callout`
- 不得把论文式前置信息压缩成普通导语段落
- 不得把摘要重新渲染成公众号导语卡片或提示块
- 不得把论文表格做成带底色的产品规格表或知识卡片

### `apple-style-template`

组件锚点：

- `eyebrow` 居中、灰色、全大写
- `h1` 居中、系统文档感
- `lead` 居中窄宽段落
- `callout` 为近白浅灰卡片，圆角更大
- `h2` 为细底线分节
- `h3` 为全大写小标题
- 表格为冷白灰整表底色，接近系统规格表气质，题签字号略大于其他主题，单元格字级较正文小一号

禁止漂移：

- 不得改成左强调线章节标题
- 不得把 `callout` 做成高饱和强调卡

### `claude-code-template`

## 组件一致性检查清单

生成前或复评时，至少检查：

- 主题是否已正确归一化到内置主题名
- 当前主题无法映射的组件是否已整篇回退到微信原生主题，而不是回退到基础样式或自拟样式
- `eyebrow` 是否只出现在本主题支持的场景中
- `callout` 是否匹配该主题的边框、背景、圆角和标签写法
- `h2` 是左线、下边线、胶囊还是纯文本，是否与本文件一致
- `h3` 是纯文本、胶囊、小块还是左细线，是否与本文件一致
- `quote` 的背景、边线和圆角是否一致
- 除 `academic-paper-template` 外，正文段落、提示块正文与收尾是否未使用首行缩进
- 表格题签与表格说明是否符合本文件约束
- 表格是否保持整表主题底色体系，而不是只剩首行或首列着色
- 表格单元格文字是否比正文小一号，且没有误伤题签与说明文字层级
- 代码块底色、边框和字体是否一致

任一项不一致，都应视为主题漂移，必须修正。
