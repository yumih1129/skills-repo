# 内容格式标准

本文件承接发布源稿、正文 Markdown 与公众号可读性细则。`SKILL.md` 保留核心流程与硬约束；本文只展开执行细则，不改变主流程。

## 发布源稿标准

发布源稿是本技能的第一核心交付物，必须固定为以下四部分：

- `标题`：用于公众号标题展示，长度不得超过 64 字
- `摘要`：用于公众号摘要或导语区，长度不得超过 120 字
- `封面提示词`：用于生成或设计封面的完整中文提示词，应包含主体、风格、构图、色调、文字处理要求和禁用项
- `正文 Markdown`：用于正文排版与最终 HTML 渲染的标准 Markdown 正文

发布源稿的整理原则：

- `title`、`summary`、`cover_prompt`、`markdown` 必须表达同一篇文章，不能标题在讲 A、正文在讲 B。
- `summary` 不是正文第一段的随手截取，而是对全文的准确概括；过长必须压缩到 120 字内。
- `cover_prompt` 必须始终生成，不能省略；即使用户不关心封面，它也必须作为源稿字段保留。
- `markdown` 只承载正文，不重复写 `标题：`、`摘要：`、`封面提示词：` 等元数据。
- `markdown` 是最终 HTML 的读者可见正文基准，只能承载对用户输入内容的忠实汇总、总结、重组和必要衔接；不得写入源稿文件、`source.md`、`final.html`、`cover_prompt`、封面提示词保存位置、原始链接保留位置、二次编辑、复核路径、导出文件、执行过程或资产管理说明。
- 若用户输入的 Markdown 自带一级标题，必须先抽取并归一化到 `title`，再从正文 Markdown 中移除该 `#` 标题，避免源稿重复。
- 若用户输入的开头导语足以提炼摘要，可压缩后进入 `summary`；正文中是否保留扩展版导语，应以阅读完整性为准，但不能与摘要机械重复。

## 正文 Markdown 语法标准

Step 2 产出的正文 Markdown 必须是可直接审阅、可直接继续转 HTML 的标准正文，不是松散草稿。默认采用以下固定语法子集：

正文 Markdown 生成前必须先完成成稿整理门禁：

- 先理解原文核心问题、事实链、论证顺序、情绪边界和用户明确保留项。
- 再抽取必须保留的信息单元，包括事实、时间、数字、引用、判断、因果关系、并列关系和限制条件。
- 再建立全文内部排版模式表，识别背景、事实、原因、影响、观点、案例、步骤、风险、建议、结论等信息类型，并为每类信息固定一种 Markdown 呈现方式。
- 再决定每个信息单元进入段落、列表、引用、表格、代码块或图片说明，不把并列信息挤进逗号链，也不把散文硬拆成伪列表。
- 同一篇文章中的同类信息必须同构呈现；不得让同一种信息前半篇用自然段、后半篇改成列表、引用、表格或提示块，除非原文信息类型已经发生变化。
- 再组织 `##` 与必要的 `###`，章节标题必须准确、具体、有信息量，不得使用“第一部分 / 第二部分 / 其他说明”这类空标题。
- 最后从最终 HTML 效果反推发布级排版审校，检查段落长度、层级、节奏、留白、重点呈现、同类内容排版一致性和手机端连续阅读体验；套用目标主题后必须美观、大气、规范，不能依赖 HTML 阶段临时补救正文结构。

- 正文 Markdown 不再包含一级标题；`title` 已外提为源稿字段。
- 主章节必须使用 `##`；局部小标题仅在确有必要时使用 `###`。
- 禁止出现 `####` 及更深层级，避免手机端层级失控。
- 正文开头可先有 1 到 2 段引入段，但不得再额外重复标题。
- 段落之间必须留 1 个空行；不得把多段内容硬并成一个大段，也不得为了换行好看插入大量空行。
- 普通正文使用自然段，不使用伪列表、伪标题、全角装饰符或手工缩进字符模拟结构。
- 并列信息使用标准列表：无序列表只用 `-`，有序列表只用 `1.` 风格。
- 引述必须使用 `>`，不能把引用原话混入普通正文冒充作者叙述。
- 对比型信息才允许使用表格；表格必须有表头，且列含义清楚。
- 代码、命令、配置片段必须使用三反引号代码块；语言可识别时应标注语言。
- 不允许在 Markdown 正文里混入原始 HTML 标签、内联样式、占位 `div` 或仅供视觉装饰的分隔符。
- 图片信息若有真实链接，使用标准 Markdown 图片语法；若只有图片意图没有链接，只保留“图片说明/图片位置”文字，不伪造资源地址。

Markdown 结构化整理的硬约束：

- 标题必须能准确概括全文，不得偷换原文主旨。
- 摘要必须先交代文章主题、对象或核心结论，不得写成空泛宣传语。
- 每个 `##` 章节只承载一个主话题；不同主话题必须拆章。
- `###` 只能作为 `##` 的从属展开，不能跳级单独出现。
- 列表项必须平行、同类、可并列阅读，不能把整段散文硬拆成列表。
- 表格与代码块前后应有过渡句或说明，避免内容突然断裂。

## 正文排版一致性标准

正文排版一致性只约束结构呈现，不授权改写原文事实、立场、数字、引用或用户明确要求保留的表达。

内部排版模式表：

- 生成正文前，必须先在执行上下文中确定全文内部排版模式表；该表不对用户默认展示，不写入文件。
- 排版模式表至少判断背景、事实、原因、影响、观点、案例、步骤、风险、建议、结论等信息类型是否出现。
- 每类已出现的信息必须固定一种主要 Markdown 呈现方式：自然段、无序列表、有序列表、引用块、表格、代码块、图片说明或主题可承接的提示块语义。
- 一旦某类信息确定了呈现方式，全文同类信息必须沿用；只有原文信息类型发生变化时，才允许切换呈现方式。

段落一致性：

- 普通段落只承载一个核心意思；同一段内不得混入多个并列结论、多个步骤或多个互不从属的事实。
- 同一类解释性内容必须保持相近粒度；不得前文使用短段解释，后文改成长段堆叠。
- 连续短句若共同说明同一意思，应合并为自然段；连续并列项超过 3 项时，优先改为列表。
- 同一类章节若都需要引入段，则每个同类章节都应保留引入段；若不需要，则都直接进入主体内容，不前后混用。

列表一致性：

- 只有同类、平行、可并列阅读的信息才能列表化。
- 同一列表内的列表项必须保持同一种语法形态：全部为名词短语、全部为动宾短语，或全部为完整句。
- 列表项需要解释时，统一使用“列表项：解释”的格式；不得有的只写短语、有的写成多句段落。
- 同一类信息在全文中若已经使用列表呈现，后续同类信息不得改成连续自然段，除非原文不再是并列关系。
- 同一小节内连续出现两个列表时，必须合并为一个列表，或用过渡段说明两个列表的语义差异。

引用与提示块一致性：

- 原文直接引语必须使用引用块；非原话的作者观点、判断或总结不得伪装成引用。
- 全文同类重点提示只能固定使用一种呈现方式：引用块、主题支持的提示块语义，或普通段落；不得前后混用。
- 提示块只用于全篇关键提示、研究提示、方法说明、风险提示或核心发现，不得作为普通段落的装饰替代。
- 若某主题无法承接提示块语义，应按主题规则回退或改用普通段落、引用块，不得自造提示块样式。

章节一致性：

- 同级 `##` 标题必须保持同一种命名风格：都用判断式、都用问题式，或都用名词短语式；不得在同级标题中混用多种风格。
- 同一类章节的内部结构必须尽量一致；例如“背景 -> 影响 -> 应对”结构出现一次后，后续同类章节不得改成纯列表或纯段落。
- `###` 只能作为 `##` 的从属展开；同类 `###` 标题也必须保持命名风格和信息粒度一致。
- 若某个同级章节因原文内容不足无法保持同构，应压缩为普通段落或并入相邻章节，不得硬造空标题。

表格一致性：

- 同类对比信息超过 2 组时优先使用表格；若全文已用表格表达某类对比，后续同类对比应继续使用表格。
- 表格必须有明确列名，列名的语法风格必须一致。
- 表格前必须有一句说明该表比较什么；表格后如需总结，只保留一段结论，不重复表格全部内容。
- 无法对齐比较维度的信息不得硬塞进表格，应改用自然段或列表。

全文一致性复查：

- 同类内容是否都使用同一种 Markdown 结构。
- 同级标题是否风格一致、信息粒度一致。
- 列表项是否平行、同类、语法形态一致。
- 引用、表格、提示块是否都有真实内容需要，而不是为了视觉变化临时加入。
- 是否存在同一种信息前文用列表、后文用自然段、引用或表格的混排。
- 是否存在源稿文件、封面提示词、导出文件、原始链接保留位置、二次编辑、复核路径或执行过程说明等与用户原文内容无关的元信息；若存在，必须删除。
- 是否为了排版整齐改变了原文事实、数字、引用、判断关系或语气边界；若存在，必须回退。

## 公众号美化排版标准

“美化、精美、整齐”不是主观感受，而是必须满足以下排版标准：

- `层级清楚`：读者一眼能分辨标题、摘要、章节、小标题、引用、表格和收尾，不出现视觉层级混乱。
- `段落整齐`：正文段落长度适中，单段通常只承载一个意思；过长段必须拆开，过碎句子不得一行一段。
- `节奏稳定`：正文、列表、引用、表格、代码块应穿插有序，避免连续堆叠多个高强调块导致页面发花。
- `重点明确`：真正重要的信息优先通过标题、摘要、列表、引用或表格自然显现，而不是靠口号式加粗堆砌。
- `留白合理`：章节之间有明确呼吸感，但不能为了“好看”制造空洞页面。
- `风格统一`：最终 HTML 中每个组件都必须严格服从所选主题，不允许同文混入多个主题语法。
- `手机端友好`：成稿默认按微信公众号手机阅读体验整理，避免超长标题、超密列表、超宽表格和连续大段说明。

Markdown 阶段就必须完成的美化整理动作：

- 把冗长口语句切分为适合手机端阅读的自然段。
- 把并列观点、步骤、条件、建议整理成列表，而不是挤在逗号链里。
- 把可比较信息整理成表格，把结论性原话整理成引用。
- 给每个主要章节补上足够明确的章节标题，避免“第一部分/第二部分”这类空标题。
- 让摘要、正文、收尾在信息密度上形成清晰节奏，避免全文从头到尾一个语气一个形态。
